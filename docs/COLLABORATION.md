## Working across boundaries

- State why a cross-area change is needed and keep it within the owner's
  authorized scope. Coordinate changes to shared interfaces and avoid parallel
  edits that overwrite another contributor's work. Ownership is coordination,
  not a blanket prohibition against helping.
- The primary implementer makes the change and its appropriate checks; the
  reviewer checks assumptions, integration and practical limits. The owner
  decides subjective feel and appearance at the agreed milestone.
- Start by inspecting the current branch and uncommitted changes. Preserve
  existing work. Restore only specific, inspected files generated by your own
  command; never use automatic whole-folder cleanup.
- Keep confirmed game decisions and frozen checkpoints intact. Record project
  state separately from communication preferences. Do not silently promote a
  suggestion into an approved decision.
