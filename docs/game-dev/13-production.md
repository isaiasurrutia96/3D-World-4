# 13 — How Games Are Made (Process)

## A) Stages

1. **Concept:** what is the core action and why is it fun? One sentence.
2. **Prototype:** test the core action with plain shapes (gray boxing). Nintendo
   famously starts with the controls and camera before any levels — Super
   Mario 64's team built the camera system first and tested Mario in an empty
   room until moving felt good.
3. **Vertical slice:** one small piece of the game at final quality, to prove
   the whole pipeline.
4. **Production:** build content (levels, modes) on top of the proven core.
5. **Polish:** juice, audio, performance, bugs. Often the longest stage.
6. **Release and updates.**

## B) Habits of successful teams

1. **Iterate fast on feel.** Change a number, play, repeat. Keep tuning values
   in one place.
2. **Playtest with others** early and watch them silently; what confuses them
   is the real bug list.
3. **Small scope, finished.** A small polished game beats a big unfinished one.
4. **Keep the game playable every day**; never break the build for long.
5. **Checkpoints/backups** before risky changes (version control branches).
6. **Measure performance** on the weakest target device, not the best one.
7. **Decide, record, keep:** write down decisions so they aren't relitigated.

## C) Roles in a studio (who does what)

1. Game designer (rules, tuning), level designer, programmer (gameplay,
   engine, tools, network), technical artist, 3D artist, animator, sound
   designer, composer, UI/UX designer, QA tester, producer.
2. In a one-person-plus-AI project, the owner is director and designer; the AI
   should implement exactly what is asked and keep the build working.
