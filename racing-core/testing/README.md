# Driving-feel test

This is the small checked adapter used by `/racing-lab/?drive=1`. It connects the approved handling and contact modules, exposes interpolated poses, and offers explicit Reset and scenario selection.

`readDrivingInput` consumes the existing shared Motion Lab snapshot. It recovers independent throttle/steering axes, preserves analog steering, removes numerical residue and keeps keyboard diagonals at full strength. Phone Left/Right/Gas/Reverse actions are camera-independent. Brake/Reverse supplies the original negative pedal command; Space/LT supplies the independent stop brake. Gas + Reverse brakes rather than accelerating. Boost remains a granted test command with the checked edge behavior. A pause cancels a queued activation without resetting the kart's position or physics clock.

`createDrivingTest` supports all four circuits for solo driving. The Parked Karts selection uses Original Circuit and adds two initially stationary karts. All three participate in the same contact solve on the player controller’s 120 Hz clock. The target states commit with the player’s frame batch. Rendering reads `sample()` and `sampleParked()`. Reset restores the active scenario’s starting positions and clears motion and timers.

Run `npm run test:racing-drive`. Node checks cover camera-independent input, actual chase-camera turn direction, cancellations, frame splits, the original model and strict ES2022 typechecking. Parked Karts checks cover impact transfer to both targets, frame-rate agreement, reset, and rollback after an interrupted frame. Reports record rule/input/measurement/PASS in CHECK-RESULTS.md/json. The existing full racing test command imports these checks. Actual browser controls/layout are checked by `npm run test:racing-drive-browser` after building. The owner still needs to judge driving feel; code checks cannot approve it.
