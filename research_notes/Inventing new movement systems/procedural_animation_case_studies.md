## 1. Overgrowth (Wolfire Games, David Rosen, GDC 2014 "An Indie Approach to Procedural Animation"): how a few key poses plus physics-like interpolation produced fluid movement

### Takeaway
Rosen's method is to author a very small set of key poses (reportedly four for a walk or run cycle: pass and reach for each side) and let code produce the in-between motion: interpolation weighted by speed, shaped curves (including spring-style interpolation), and ragdoll/physics layers. Because these pieces respond to game state every frame instead of replaying clips, the result looks fluid and interactive while costing very little authoring time, which suited a tiny indie team.

### Cited Findings
- **The talk itself:** a GDC 2014 Animation Bootcamp session by David Rosen (Wolfire Games). The official description: "simple procedural techniques to achieve interactive and fluid animations using very few key frames," with examples from Overgrowth, Receiver and Black Shades. — [GDC Vault listing](https://gdcvault.com/play/1020049/Animation-Bootcamp-An-Indie-Approach)
- The session was about 30 minutes long. One viewer praised it as worth watching for ideas on "how far procedural algorithms can enhance animation"; another wished it had gone deeper into technical detail. — [Unity forum thread on the talk](https://discussions.unity.com/t/an-indie-approach-to-procedural-animation-gdc-video-talk/538228)
- Overgrowth is not purely procedural: "a lot of the animation in Overgrowth is controlled by keyed poses," and the talk has sections titled "Refinement" and "Ragdoll." (secondary: forum commenter) — [Polycount discussion](https://polycount.com/discussion/comment/2093086)
- A Polycount commenter says the talk covered "spring interpolation," which Rosen described as an animation curve he uses often. (secondary; exact comment not verified) — [Polycount discussion](https://polycount.com/discussion/comment/2093477)
- A forum summary of the talk claims the system used only 13 keyframes in total for everything. (secondary, unverified number) — [Handmade Network thread "Coding Animations using Very Few Keyframes"](https://hero.handmade.network/forums/code-discussion/t/2522/p/12898)
- A Texas A&M student reimplementation of the Overgrowth approach builds each walk and run cycle from four keyframes: a pass and a reach pose for each side. For speeds between walk and run it interpolates joint angles in proportion to speed, using spherical interpolation of local joint quaternions because the poses differ so much. (secondary reimplementation) — [TAMU CSC474 student demo](https://people.engr.tamu.edu/sueda/courses/CSC474/2016W/demos/ismithgr/index.html)
- Wolfire's own blog wrote about this kind of pose blending as early as 2010, in a post on "angular and linear keyframe blending" for Overgrowth's rolling animation. This shows the pose-interpolation approach was developed over several years before the 2014 talk. — [Wolfire blog, April 2010](https://wolfire-blog.appspot.com/2010/04/Angular-and-linear-keyframe-blending)
- People reimplementing it found that two poses with plain linear interpolation already looked "good enough", but that matching Rosen's results needed curve-shaped transitions. They also concluded Wolfire probably used a custom engine with poses and curves interpolated at runtime. — [GameDev.net thread](https://www.gamedev.net/forums/topic/685275-is-procedural-animation-by-poses-based-on-overgrowth-possible-on-unity/); [Unreal forum WIP "Overgrowth style" pose blending](https://forums.unrealengine.com/t/wip-pose-based-animation-blending-overgrowth-style/27768)
- In the talk, Rosen also answers general game animation questions, such as the difference between a playable character and a vehicle. — [Game Developer video post](https://gamedeveloper.com/design/video-an-indie-approach-to-procedural-animation)

### Inferences
- The core idea is to treat key poses as targets and interpolation as a dynamic system (curves, springs, speed-driven blend weights), not as fixed timing. Motion then follows gameplay variables such as velocity and contacts automatically. This is a borrowing from physics (damped springs) into keyframe animation.
- The iteration path visible in sources runs from the 2010 blog post on keyframe blending, through the full Overgrowth system, to the 2014 talk. It looks like long, incremental refinement inside one custom engine, not a single breakthrough. Treat this as inference from dates, not something Rosen stated.
- Why the existing method did not fit: a large clip library with blend trees costs a lot of authoring and makes transitions hard to keep responsive. A few poses plus code was the only option a small team could afford. (inference; consistent with the talk's "very few key frames" framing)

### Gaps
- The full talk, slides and transcript could not be opened, so I could not confirm Rosen's own account of how he arrived at the method, the exact spring formulation, or how ragdoll blending was done.
- Unverified recollection: the talk shows a run cycle with very few poses per stride, eased by curve shaping; a jump or fall built from a few poses blended by vertical velocity; landings and body bob driven by spring-damper motion; and an active-ragdoll layer for hits and falls. Confirm against the [GDC Vault video](https://gdcvault.com/play/1020049/Animation-Bootcamp-An-Indie-Approach) before using.

## 2. Spore's procedural creature animation (Hecker et al., SIGGRAPH 2008 "Real-time Motion Retargeting to Highly Varied User-Created Morphologies")

### Takeaway
Spore had to animate creatures that did not exist when the animations were authored. Hecker's team kept the familiar animator workflow (posing and keyframing), but stored the motion in a morphology-independent, semantically annotated form. At runtime this data is specialized to each creature's body and turned into pose goals for an inverse kinematics solver tuned for creature morphologies. Hecker's GDC 2007 talk openly covered "what worked and what didn't."

### Cited Findings
- **Citation:** Chris Hecker, Bernd Raabe, Ryan W. Enslow, John DeWeese, Jordan Maynard, Kees van Prooijen. ACM Transactions on Graphics 27(3), August 2008, presented at SIGGRAPH 2008. — [Hecker's paper page](https://chrishecker.com/Real-time_Motion_Retargeting_to_Highly_Varied_User-Created_Morphologies); [ACM DOI](https://doi.org/10.1145/1360612.1360626)
- **Problem:** game character animation traditionally depends on fixed skeletons set early in development. Spore's creatures are made by players, so their skeletal shapes are unknown when the animations are authored. — [SIGGRAPH History Archive entry](https://history.siggraph.org/?p=112832); [Hecker's paper page](https://chrishecker.com/Real-time_Motion_Retargeting_to_Highly_Varied_User-Created_Morphologies)
- The GDC 2007 talk "How To Animate a Character You've Never Seen Before" framed the core problem as "most of the content in the game will be made after the game ships", with creatures of almost arbitrary shape and skeleton topology. The lecture covers the approaches tried for procedurally animating user-made creatures, "including what worked and what didn't." — [Hecker's GDC 2007 talk page](https://chrishecker.com/How_To_Animate_a_Character_You%27ve_Never_Seen_Before)
- **Technique:** animators use familiar posing and keyframing in an authoring tool. The system records the motion in a morphology-independent form, with animators adding semantic information about each motion. At runtime the generalized motion is specialized onto each creature's morphology to produce pose goals for an IK solver. — [Hecker's paper page](https://chrishecker.com/Real-time_Motion_Retargeting_to_Highly_Varied_User-Created_Morphologies); [paper PDF copy hosted by Chalmers](https://www.cse.chalmers.se/edu/year/2011/course/TDA361/Advanced%20Computer%20Graphics/027-hecker%20copy.pdf)
- The IK solver was tuned to handle creature morphologies; a blog review describes it as the team's "own ad hoc IK solver." — [paperdecoder blog review (informal)](https://paperdecoder.blogspot.com/2008/07/real-time-motion-retargeting-to-highly.html)
- A Computer Graphics World feature says a scripting language gave particles access to the creature's morphology. (secondary; context not verified) — [CGW, "Evolutionary Chain", Oct 2008](https://www.cgw.com/Publications/CGW/2008/Volume-31-Issue-10-Oct-2008-/Evolutionary-Chain.aspx)
- **Critique:** an informal reviewer called the approach fairly ad hoc and built mainly to run in real time for the game. This is a fair hint that it was engineered for production, not derived from theory. — [paperdecoder blog](https://paperdecoder.blogspot.com/2008/07/real-time-motion-retargeting-to-highly.html)
- EA/Maxis's press release presented the paper as an inside look at the authoring tool behind Spore's creatures. — [Renderosity press item](https://www.renderosity.com/spore-experts-share-animation-techniques-at-siggraph-2008-cms-14139)

### Inferences
- The key inversion: instead of replacing animators with pure procedural motion, the team changed what an animation is. It stops being joint rotations for a known skeleton and becomes intent ("this hand reaches this relative target", "these feet are grounded"), which a solver can carry out on any body. This "semantic layer plus solver" split is the reusable idea.
- The team published its failures (GDC 2007 "what worked and what didn't"), then a polished paper a year later at SIGGRAPH. The sequence was production first, academic writeup second.

### Gaps
- I could not open the paper or talk, so the specific approaches that failed, the details of the IK solver, and how gait/leg cycles were generated are unconfirmed.
- Unverified recollection: Spore separated authored, retargeted animations from a procedural gait/locomotion system, and the talk described earlier dead ends before settling on semantic retargeting. Check the [GDC 2007 talk page](https://chrishecker.com/How_To_Animate_a_Character_You%27ve_Never_Seen_Before), which hosts the slides.

## 3. Ubisoft motion matching (Büttner and Clavet 2015; Clavet GDC 2016; Zadziuk GDC 2016) and Learned Motion Matching (Holden et al. 2020)

### Takeaway
Motion matching came from discarding the hand-built animation state machine. Instead, every frame (or every few frames) it brute-force searches a large, lightly structured motion-capture database for the frame whose features (current pose plus the desired future trajectory) best match what gameplay wants, then jumps there. It started as a greedy simplification of the academic Motion Fields method, shipped first in For Honor, and spread to The Last of Us Part II and to engine tools. Its main cost was memory, which Holden's Learned Motion Matching (2020) addressed by replacing each stage of the algorithm with a small neural network while keeping the same behaviour.

### Cited Findings
- **Origin:** Michael Büttner and Simon Clavet presented "Motion Matching - The Road to Next Gen Animation" at Nucl.ai 2015. A later paper describes it as "a greedy approximation to Motion Fields (Lee et al., 2010)," which was "significantly advanced for Ubisoft's For Honor [Clavet 2016]." — [arXiv 2510.22632 (literature review)](https://arxiv.org/html/2510.22632v1)
- Büttner also presented "Motion Matching - Road to Next-Gen Animation" at CEDEC 2016 in Japan. — [CEDEC 2016 session page](https://2019.cedec.cesa.or.jp/2016/session/VA/14910.html)
- **GDC 2016:** "Motion Matching and The Road to Next-Gen Animation," Simon Clavet, Ubisoft Montreal, programming track. — [GDC Vault listing](https://www.gdcvault.com/play/1022985/Motion-Matching-and-The-Road)
- **Core idea and stance:** the system searches all of the motion capture data every frame and moves to the best-matching frame. This is very demanding on memory and CPU, and Clavet called it a deliberately "brute-force" animation system. The stated goal was "precise gameplay" together with "convincing animation," two aims that usually conflict. — [Game Watch (Impress) GDC 2016 report, Japanese](https://game.watch.impress.co.jp/docs/news/749136.html)
- **Query construction:** a feature vector is built from the current pose and the upcoming part of the desired path, and the database entry that best matches it is chosen. — [arXiv 2510.22632](https://arxiv.org/html/2510.22632v1)
- **Feature choice:** the matching needs only a few bones, mostly foot positions and velocities, plus the weapon position in For Honor. (secondary summary of Clavet's talk; exact source attribution not verified) — [arXiv 2510.22632](https://arxiv.org/html/2510.22632v1); [goodrain553 blog on motion matching](https://goodrain553.github.io/posts/motionMatching)
- Clavet's nucl.ai 2016 follow-up, "Motion Matching For Realistic Animation in For Honor," spends the rest of the talk on "procedural touch-ups" layered on top of the search. — [Game Developer, "Most Inspiring Game Animation Tech Talks of 2016"](https://gamedeveloper.com/programming/most-inspiring-game-animation-tech-talks-of-2016)
- **Zadziuk's role:** Ubisoft Toronto animation director Kristjan Zadziuk presented the technique from the animator's side. Press called it "an innovative animation technique" that "could bring a significant shift in the field." Press reports conflict on who gave which session: the GDC Vault credits Clavet with "Motion Matching and The Road to Next-Gen Animation," while GameAnim lists a Zadziuk talk titled "Motion Matching: The Future of Gameplay Animation Today," which he shared after GDC 2016. — [GameWatcher](https://gamewatcher.com/news/2016-15-03-ubisoft-working-on-motion-matching-new-animation-technology); [DualShockers](https://www.dualshockers.com/ubisoft-introduces-motion-matching-the-first-step-to-next-gen-animation/); [GameAnim tag page](https://www.gameanim.com/tag/kristjan-zadziuk/); [GamingBolt](https://gamingbolt.com/ubisoft-introduces-the-next-generation-of-animation-at-gdc)
- **"Dance cards":** Zadziuk and his team (GDC 2016 Animation Bootcamp: Motion Matching) "gave this some structure and worked out a set of dance cards," meaning structured mocap capture scripts. The source does not list their contents. — [O3DE blog, "Motion Matching in O3DE"](https://docs.o3de.org/blog/posts/blog-motionmatching/)
- **Spread:** Naughty Dog describes switching to "a pretty experimental animation system called Motion Matching" for The Last of Us Part II as "a leap of faith," and says the game was praised for animation quality. — [Naughty Dog blog, GDC 2021](https://www.naughtydog.com/blog/naughty_dog_at_gdc_2021); [GDC Vault, Motion Matching in The Last of Us Part II](https://gdcvault.com/play/1027118/Motion-Matching-in-The-Last); [GamingBolt on Anthony Newman's comments](https://gamingbolt.com/the-last-of-us-part-2s-new-motion-mapping-technique-provides-incredible-next-gen-leap-in-animations)
- **Learned Motion Matching (LMM):** Holden, Kanoun, Perepichka, Popa, ACM TOG 39(4), SIGGRAPH 2020. The paper calls memory use the main limitation of motion matching: animation data plus a matching-features database that grows with the number of features and the amount of data. — [Paper PDF (theorangeduck.com)](https://www.theorangeduck.com/media/uploads/other_stuff/Learned_Motion_Matching.pdf); [Ubisoft Montreal post, 30 July 2020](https://montreal.ubisoft.com/?p=22999)
- **LMM method:** the authors break motion matching into its individual steps and replace each with a learned component. The final model stores neither the animation data nor the matching metadata, aims to keep motion matching's behaviour, and its memory stays small as more data is added. One network, the "Decompressor," maps a matching feature vector to the full pose. Extra learned features can be "automatically selected to improve the Decompressor's accuracy." — [Ubisoft La Forge, "Learned Motion Matching"](https://www.ubisoft.com/en-us/studio/laforge/news/3NWqwcMU9lMfumgfPAEfka/learned-motion-matching); [Ubisoft La Forge, "Introducing Learned Motion Matching"](https://www.ubisoft.com/en-us/studio/laforge/news/6xXL85Q3bF2vEj76xmnmIu/introducing-learned-motion-matching)
- Holden's blog says the approach trains three specialized neural networks to replace three specific components of motion matching. — [theorangeduck.com, Learned Motion Matching page](https://www.theorangeduck.com/page/learned-motion-matching)
- At the time of a later Ubisoft interview, LMM had not been integrated into a shipped game, although the team considered it proven. — [Ubisoft News interview](https://news.ubisoft.com/en-us/article/27176jslYNMPt7vBfCaRQ1)

### Inferences
- How it was invented: the team took an elegant but complex research idea (Motion Fields, which uses reinforcement-learning-style value functions over motion) and kept only the part that mattered: nearest-neighbour search over a small, hand-chosen feature set. They paid for the simplicity with brute-force CPU and memory. This "make the dumbest version that could work, then optimize" move recurs in later cases.
- The shift was also organizational. The problem moved from "author and connect hundreds of clips and transitions" to "capture the right coverage" (Zadziuk's dance cards). Animators became directors of data coverage. Procedural touch-ups (foot locking, IK and similar) were kept as a separate layer on top.
- LMM repeats the pattern one level up: once a working algorithm exists, each stage can be replaced by a learned approximation and checked against the original, which acts as ground truth.

### Gaps
- The GDC Vault videos are behind a login and the slides could not be fetched, so the exact cost function, weights, trajectory-prediction method and dance-card contents are unconfirmed.
- Unverified recollection: Clavet's talk said the desired trajectory comes from a spring-damper model of player input, and that the team iterated by spotting bad in-game moments and recording targeted mocap to fill those gaps.
- Unverified recollection: LMM's three networks are called Decompressor, Stepper and Projector. Only "Decompressor" was confirmed in search extracts.
- Unverified: a search extract said Ubisoft calls For Honor the first game to use motion matching, but I could not tie that claim to a specific Ubisoft page.

## 4. Rain World, Grow Home/Grow Up, Shadow of the Colossus, Assassin's Creed, Naughty Dog layers, Spider-Man/procedural legs, and FABRIK IK

### Takeaway
The indie cases (Rain World, Grow Home) grew from a programmer making a small physics-and-code experiment and finding charm in the result, then building a game around it. The AAA cases (Assassin's Creed, Team Ico, Naughty Dog, Insomniac) mostly add procedural layers on top of authored or captured animation: IK for hands and feet, terrain adaptation, physics. Each new layer usually answered a specific failure, such as feet not matching uneven terrain or jump animations not fitting the environment. FABRIK came from academia as a deliberately simple geometric IK solver (points on lines instead of angle matrices), and its speed and simplicity made it a standard tool for procedural limbs.

### Cited Findings
**Rain World (Joar Jakobsson, with James Therrien)**
- Jakobsson started the ideas behind Rain World in 2011 while an exchange student in Seoul, and that seed was the procedural animation technique used throughout the game. He has said he did not set out to do procedural animation: he needed the slugcat's limbs to move, and he used code to do it. — [Unity blog, "Exploring procedural design in Rain World: The Watcher" (2025)](https://unity.com/blog/exploring-procedural-design-rain-world)
- Jakobsson in his own words: "Contrary to the classic Disney style of animation, where you draw every frame and then replay them, what I'm doing is I have a bunch of points in space and I connect them at certain distances." The result is soft, bendable, and "can navigate pretty much any environment placed in it." — [Game Developer, "Animating Rain World and its many squishy, stretchy creatures" (GDC 2016 Animation Bootcamp)](https://gamedeveloper.com/art/video-animating-i-rain-world-i-and-its-many-squishy-stretchy-creatures); [mirror](https://www.jikguard.com/news/video-animating-rain-world-and-its-many-squishy-stretchy-creatures)
- Game Developer called the GDC 2016 talk an approachable overview of "what's great (and tough) about implementing procedural animation in games." Jakobsson admitted the approach sometimes makes the game "difficult and frustrating." — [Game Developer](https://gamedeveloper.com/art/video-animating-i-rain-world-i-and-its-many-squishy-stretchy-creatures)
- Creatures have their own survival-driven intelligence instead of existing to serve the player, and the bestiary has grown to over 100 creatures. — [Unity blog](https://unity.com/blog/exploring-procedural-design-rain-world); [Game Developer, ecosystem article](https://gamedeveloper.com/design/crafting-the-complex-chaotic-ecosystem-of-i-rain-world-i-)

**Grow Home / Grow Up (Ubisoft Reflections)**
- Grow Home "started life as an experiment in procedural animation by a physics programmer, eventually becoming a proper game". Ubisoft says the team "saw a personality and charm in this little tool" that inspired them to turn it into something more. — [Ubisoft News, "Get ready to Grow Home" (Jan 2015)](https://news.ubisoft.com/en-us/article/7fDmgKCCwWJQtyoVoOvvGM/get-ready-to-grow-home); [Game Informer](https://gameinformer.com/b/news/archive/2015/01/22/ubisoft-unveils-innovative-procedural-platform-grow-home.aspx)

BUD's simplified body has gaps where joints would be, which makes the animation system easier to handle. — [Wikipedia, Grow Home](https://en.wikipedia.com/wiki/Grow_Home); [GameWatcher](https://www.gamewatcher.com/news/2015-23-01-ubisoft-announces-procedurally-animated-platformer-grow-home); [MCV](https://mcvuk.com/development-news/video-reflections-experimental-team-reveals-grow-home/)

**Assassin's Creed**

**Spider-Man and procedural legs**
- Insomniac's traversal talks: "Concrete Jungle Gym" (Doug Sheahan, GDC 2019) on web-swinging internals, and "Higher, Faster, Farther: Evolving Traversal in Marvel's Spider-Man 2" (GDC 2024). — [GDC Vault, Concrete Jungle Gym](https://gdcvault.com/play/1026422/Concrete-Jungle-Gym-Building-Traversal); [GDC 2024 schedule](https://schedule.gdconf.com/session/higher-faster-farther-evolving-traversal-in-marvels-spider-man-2/900249); [GDC Vault, "Thwips and Hugs: The Animation of Marvel's Spider-Man 2"](https://gdcvault.com/play/1034543/Animation-Summit-Thwips-and-Hugs)
- The common procedural multi-leg recipe is: each foot keeps a rest target (found by raycast, often predicted ahead using body velocity), a step fires when the planted foot drifts past a distance threshold, the swing follows an arc with tunable speed and height, a manager decides which legs may step (gait coordination), and the body holds a set height above the surface. — [80.lv, IK-driven spider locomotion in Godot 4.5](https://80.lv/articles/ik-driven-procedural-spider-locomotion-in-godot-4-5); [Digital Production, "Spider Walker" (Aug 2026)](https://digitalproduction.com/2026/08/28/spider-walker-automates-multi-leg-animation/); [PhilS94 Unity wall-walking spider (GitHub)](https://www.Github.com/PhilS94/Unity-Procedural-IK-Wall-Walking-Spider); [University of Tartu course project](https://courses.cs.ut.ee/2025/cg/fall/Main/Project-ProceduralAnimation)

**FABRIK (Aristidou and Lasenby 2011)**
- "FABRIK: A fast, iterative solver for the Inverse Kinematics problem," Graphical Models 73(5): 243–260. It avoids rotation angles and matrices and finds each joint's position by locating a point on a line. — [Andreas Aristidou's FABRIK page](https://www.andreasaristidou.com/FABRIK)
- It alternates a backward pass (from the end effector toward the root) with a forward pass that re-anchors the root, and repeats until the end effector is close enough to the target or an iteration cap is reached. — [Vulkan tutorial, FABRIK](https://docs.vulkan.org/tutorial/latest/Advanced_glTF/Procedural_Animation_IK/03_fabrik.html)
- The authors claim lower processing time and fewer iterations than CCD-type methods, with a simple algorithm. A later paper says it avoids singularity problems. It supports constraints and multiple chains with multiple end effectors, and a 2016 extension adds model constraints. — [FABRIK paper PDF](https://perso.liris.cnrs.fr/alexandre.meyer/teaching/master_charanim/M2_3_video_IK_Procedurale/FABRIK.pdf); [FABRIK constraints article](https://joanllobera.github.io/teaching/animation-foundations/12.03.fabrikconstraints_article.pdf); [BibSonomy record](https://bibsonomy.org/bibtex/2e10b58fcc1d783feed5a1f3e97aac4f5/achakraborty)

### Inferences
- Rain World and Grow Home show the "accidental invention" path. A programmer needs something to move, writes the simplest physical rule that could work (points kept at fixed distances; physics-driven limbs), sees that it has character, and builds the design around its strengths, accepting its quirks (Rain World's acknowledged frustration, Grow Home's tight-space bugs).
- Jakobsson's description of points at fixed distances is in effect a distance-constraint (Verlet-style) chain, the same family of technique FABRIK formalized for IK. A plausible reading is that both come from the same first-principles idea: describe a body as points plus distance constraints and solve geometrically, not by joint angles. This is inference; neither source draws the link.
- AAA studios tend to invent by layering, adding one procedural layer per observed failure (feet on stairs in ICO; jumps that don't fit the environment in AC3; predictive foot IK in 2016). They seldom replace the base animation. AC3's "redo everything, but change nothing" sums it up: new procedural machinery was judged by whether players saw the same intended motion.

## 5. Research lineage of physics-based character control (Sims 1994; Hodgins et al. 1995; SIMBICON 2007; Coros et al. 2010; DeepMimic 2018; AMP 2021): how researchers got from nothing to working controllers

### Takeaway
The lineage moves from robotics-inspired, hand-designed controllers (Raibert and Hodgins: decomposed control, foot placement for balance), to extreme simplification (SIMBICON: a pose state machine plus one linear foot-placement feedback rule), to general-purpose combinations of known robotics tools (Coros 2010: PD tracking, inverted-pendulum stepping, Jacobian-transpose virtual forces), to learning (DeepLoco, then DeepMimic: reinforcement learning that imitates mocap). Next came AMP, which replaces hand-tuned imitation rewards with a learned discriminator. Sims 1994 was a parallel branch that evolved bodies and brains together. At each step researchers kept a small, well-understood core, borrowed heavily from robotics, optimization or machine learning, and found the one or two tricks that made it work (foot placement feedback; reference-state initialization and early termination).

### Cited Findings
- **Sims 1994, "Evolving Virtual Creatures"** (SIGGRAPH '94, pp. 15–22): both morphology and the neural controllers driving muscle forces are generated by genetic algorithms. A single directed-graph genetic language describes body and neural circuitry. Different fitness functions produce swimming, walking, jumping and following. Creatures are articulated 3D rigid-body hierarchies whose neural networks process sensors and drive muscles between cuboid limbs. — [SIGGRAPH History Archive](https://history.siggraph.org/?p=119674); [paper PDF](https://course.khoury.northeastern.edu/cs5100f12/resources/reading/sims_creatures.pdf); [Wikipedia, Karl Sims](https://en.wikipedia.org/wiki/Karl_Sims)
- **Robotics root (Raibert and Hodgins 1991, "Animation of Dynamic Legged Locomotion"):** the paper is about "the use of control algorithms to animate dynamic legged locomotion," so that "control could free the animator from specifying the details of joint and limb motion while producing both physically realistic and natural looking results." It was demonstrated on a biped robot, a quadruped robot and a kangaroo. — [CMU Robotics Institute](https://ri.cmu.edu/publications/animation-of-dynamic-legged-locomotion); [SIGGRAPH History Archive](https://history.siggraph.org/?p=120604)
- The SIMBICON paper describes the Raibert line as a three-way decomposition ("control of hopping height, control of torso pitch, and control of hopping speed") and notes that "swing foot placement provides the basic mechanism for controlling balance from stride to stride." The same approach was extended to running human characters (Hodgins et al. 1995). The 3D quadruped gaits came from Raibert and Hodgins (1991), with strategies for trotting, bounding and galloping. — [SIMBICON paper PDF](https://www.cs.ubc.ca/~van/papers/2007-siggraph-simbicon.pdf); [van de Panne et al. 2011 quadruped paper](https://www.cs.ubc.ca/~van/papers/2011-TOG-quadruped/paper.pdf)
- **Hodgins, Wooten, Brogan, O'Brien 1995, "Animating Human Athletics"** (SIGGRAPH '95, pp. 71–78): control algorithms make a physically realistic human model run, bicycle and vault, including balancing while moving the arms, running or cycling at varied speeds, and a handspring vault. — [CMU RI page](https://www.ri.cmu.edu/publications/animating-human-athletics); [paper PDF](https://www.ri.cmu.edu/pub_files/pub4/hodgins_jessica_k_1995_1/hodgins_jessica_k_1995_1.pdf)
- **SIMBICON (Yin, Loken, van de Panne 2007), ACM TOG 26(3):105.** Problem: bipeds are unstable, underactuated, high-dimensional systems. Method: a finite state machine (pose control graph) whose states hold target joint-angle poses, plus "a simple linear feedback strategy for foot placement," which adjusts continuously using center-of-mass position and velocity. The hip midpoint serves as "a simple and effective proxy" for the center of mass. Result: real-time walking in all directions, running, skipping and hopping, in many styles. — [SIMBICON project page](https://cs.ubc.ca/~van/papers/Simbicon.htm); [paper PDF](https://www.cs.ubc.ca/~van/papers/2007-siggraph-simbicon.pdf); [Yin/Coros/van de Panne book chapter](https://www2.cs.sfu.ca/~kkyin/papers/BipedController.pdf)
- SIMBICON's authors set their feedback (center-of-mass position and velocity) against the earlier Hodgins/Raibert-style work, which they describe as relying on velocity. (the SIMBICON authors' characterization; exact wording unverified) — [SIMBICON paper PDF](https://www.cs.ubc.ca/~van/papers/2007-siggraph-simbicon.pdf)
- **Coros, Beaudoin, van de Panne 2010, "Generalized Biped Walking Control"** (ACM TOG 29(4)): combines PD tracking, inverted-pendulum foot placement, and Jacobian-transpose control to correct gravity and velocity errors. It runs in real time, needs no character- or motion-specific tuning, and is robust to disturbances. The paper calls Jacobian-transpose virtual forces "fundamental to force-based control in robotics." Source code (Cartwheel-3D) was released. — [UBC project page](https://www.cs.ubc.ca/~van/papers/2010-TOG-gbwc); [paper PDF](https://www.cs.ubc.ca/~van/papers/2010-TOG-gbwc/paper.pdf); [CMU RI abstract](https://www.ri.cmu.edu/publications/generalized-biped-walking-control)
- **DeepLoco (Peng, Berseth, Yin, van de Panne 2017):** a two-level hierarchy. Low-level controllers produce robust walking that meets stepping-target and style objectives, and high-level controllers plan step targets. Both are trained with deep RL. Peng's MSc thesis found that higher-level actions with local feedback (such as target angles) greatly improve performance and learning speed. — [DeepLoco project page](https://xbpeng.github.io/projects/DeepLoco/index.html); [Peng MSc thesis page](https://xbpeng.github.io/projects/MSc_Thesis/index.html)
- **DeepMimic (Peng, Abbeel, Levine, van de Panne 2018):** example-guided deep RL that imitates reference clips. Ablations identify "reference state initialization and early termination" as "critical for achieving highly dynamic skills." Reference state initialization starts each episode from a state sampled along the reference motion. Early termination ends the episode when the torso or head touches the ground, which removes local optima "such as those where the character falls and mimes the motions as it lies on the ground." — [arXiv 1804.02717](https://arxiv.org/abs/1804.02717); [project page](https://cs.ubc.ca/~van/papers/2018-TOG-deepMimic/index.html)
- **AMP (Peng, Ma, Abbeel, Levine, Kanazawa 2021):** splits the objective into a hand-designed task reward (the "what") and a learned, task-agnostic style reward (the "how"). The style reward is a discriminator trained to tell dataset motion from the character's motion, so it scores general similarity to the whole dataset instead of tracking one clip. The term "adversarial motion prior" is borrowed from adversarial pose priors in vision-based pose estimation. One prior can be reused across tasks. — [arXiv 2104.02180](https://arxiv.org/abs/2104.02180); [SIGGRAPH History Archive](https://history.siggraph.org/?p=121260)

### Inferences
- How they proceeded from nothing, as the citations show it:
  1. **Borrow a working controller from another field.** Raibert's hopping robots gave animation its first dynamic locomotion controllers, with foot placement for balance as the key lever.
  2. **Simplify until it is robust.** SIMBICON reduced biped control to a few target poses plus one linear balance rule, with an easy proxy (hip midpoint) for a hard quantity (center of mass).
  3. **Generalize with standard robotics tools.** Coros et al. combined well-known pieces (PD control, inverted pendulum, Jacobian transpose) to remove per-character tuning.
  4. **Replace hand design with optimization or learning, then fix the training dynamics.** DeepLoco, then DeepMimic, where the breakthrough was two training tricks found by ablation, not a new network.
  5. **Replace the remaining hand-tuned piece (the imitation reward) with learning,** borrowing GAN ideas from vision (AMP).
- A practical point running through this lineage: the authors released code (SIMBICON, Cartwheel-3D, DeepMimic). That made each step easy for the next group to build on. (Code release for SIMBICON and Cartwheel is cited above; DeepMimic code release is unverified here.)
- Sims's method (evolve body and brain together) ran in parallel and rewarded open-ended discovery over hand engineering. Its echo can be seen in Spore's "unknown morphology" problem, though Spore solved it with retargeting, not evolution.

### Gaps
- Unverified recollection: Hodgins 1995 used per-behaviour state machines with hand-tuned PD servos at each joint. SIMBICON's insight included controlling the torso and swing hip in the world frame, with gains often written cd and cv. DeepMimic's reward combines pose, velocity, end-effector and center-of-mass terms, and its policy takes a phase variable. None of this was confirmed in fetched text.
- I found no first-person account (interview or blog) of how the SIMBICON or DeepMimic authors came up with their key tricks. The "ablation" framing in DeepMimic is the closest evidence of an experiment-driven path.
- I did not research Sims's own account of his process (compute budget, failed experiments).

## 6. Natural variation: how systems avoid identical repeated motions

### Takeaway
Four families of technique appear: (1) coherent noise layered on procedural parameters (Perlin 1995/Improv 1996), which conveys the "texture" of motion without simulating dynamics; (2) learned statistical models that generate new variants of example motions (Lau, Bar-Joseph, Kuffner 2009), which explicitly reject variation as "just additive noise"; (3) systems that react to their surroundings (physics, terrain, friction, foot prediction), so motion differs whenever the situation does; and (4) data-driven selection or learned priors (motion matching, AMP), where motion is drawn from or scored against a large varied dataset instead of looping one clip.

### Cited Findings
- **Perlin 1995, "Real Time Responsive Animation with Personality"** (IEEE TVCG 1(1): 5–15): "rhythmic and stochastic noise functions are used to define time varying parameters that drive computer generated puppets." Because it conveys "just the 'texture' of motion," it avoids "computation of dynamics and constraint solvers." Its roots are in procedural texture synthesis. — [IEEE Xplore](https://ieeexplore.ieee.org/document/468392)
- **Improv (Perlin and Goldberg 1996)** generalizes the 1995 system. Most actions vary a few degrees of freedom over time using combinations of sine, cosine and coherent noise, with coherent noise treated as key to realism. The goal is actors whose personalities and moods stay consistent with the author's intent. — [Improv paper](https://mrl.cs.nyu.edu/~perlin/improv-paper); [NYU MRL Improv project](https://mrl.cs.nyu.edu/projects/improv/)
- **Lau, Bar-Joseph, Kuffner 2009, "Modeling Spatial and Temporal Variation in Motion Data"** (ACM TOG 28(5):171): from a few examples, a Dynamic Bayesian Network learns a generative model that synthesizes spatial and temporal variants "statistically similar to the input examples." New variants keep the features of the originals without being exact copies, generation is efficient, and memory use is small. The motivation: people never perform an action exactly the same way twice, prior work treated variation as additive noise, and crowd simulations often repeat a few clips. — [Paper PDF (Princeton course copy)](https://www.cs.princeton.edu/courses/archive/spring11/cos598A/pdfs/Lau09.pdf); [Lancaster repository](https://eprints.lancs.ac.uk/id/eprint/49898/); [Lau CMU PhD thesis](https://www.csd.cmu.edu/sites/default/files/phd-thesis/CMU-CS-09-148.pdf)
- **Physics and environment reactivity:** Grow Home's foot strikes and limb motion are generated on the fly, not taken from a limited set of preplanned loops. Rain World's point-and-distance bodies "can navigate pretty much any environment." Team Ico tried to make procedural animation account for ground friction automatically. — [GameWatcher](https://www.gamewatcher.com/news/2015-23-01-ubisoft-announces-procedurally-animated-platformer-grow-home); [Game Developer, Rain World talk](https://gamedeveloper.com/art/video-animating-i-rain-world-i-and-its-many-squishy-stretchy-creatures); [genDESIGN interview](https://gendesign.co.jp/qa_01/interview04en.html)
- **Procedural legs:** foot targets are predicted from velocity and re-stepped by a distance threshold, so step timing depends on the actual path and terrain, not a fixed cycle. — [Digital Production, Spider Walker](https://digitalproduction.com/2026/08/28/spider-walker-automates-multi-leg-animation/); [80.lv Godot spider](https://80.lv/articles/ik-driven-procedural-spider-locomotion-in-godot-4-5)
- **Learned style priors:** AMP's discriminator scores similarity to a whole dataset instead of one clip, and different priors can train the same task in different styles. — [arXiv 2104.02180](https://arxiv.org/abs/2104.02180)

### Inferences
- Motion matching likely varies naturally because the search can land on different, nearly equivalent frames of a large unstructured database, depending on small differences in pose and trajectory. I found no source that states this as a design goal, so it is inference.
- Randomized targets (for example, slightly jittered foot targets or step thresholds) are the procedural-leg version of Perlin's noise. They are inexpensive, but they can look "noisy" rather than intentional unless kept coherent over time, which is Perlin's point about using coherent noise rather than white noise. (inference built on the cited Perlin and Improv findings)

### Gaps
- I found no primary source on how Overgrowth, Rain World or motion-matching games specifically add variation (noise on poses, randomized timing, idle variants).
- I did not find recent (2023–2026) work dedicated to motion variation in games, such as diffusion-based motion generation used for variation. The arXiv 2510.22632 review may cover it but was not opened.

## 7. The common pattern: how these inventors worked

### Takeaway
Across games and research, new animation systems were invented by people who (a) started from a hard constraint that made the standard method impossible or too expensive, (b) built the simplest version that could possibly work, often brute force or a single physical rule, (c) borrowed a proven mechanism from another field (robotics, physics simulation, texture synthesis, nearest-neighbour search, GANs), (d) iterated in public or in a playable prototype, keeping what looked alive, and (e) kept a human-authored layer for intent or style while handing in-betweening, adaptation and balance to code.

### Cited Findings
- **A hard constraint forced the invention.** Spore: content would be made after the game shipped, with arbitrary skeletons ([Hecker GDC 2007](https://chrishecker.com/How_To_Animate_a_Character_You%27ve_Never_Seen_Before)). Overgrowth: "very few key frames" ([GDC Vault](https://gdcvault.com/play/1020049/Animation-Bootcamp-An-Indie-Approach)). For Honor: "precise gameplay" plus "convincing animation" ([Game Watch](https://game.watch.impress.co.jp/docs/news/749136.html)). Bipeds are unstable, underactuated systems ([SIMBICON](https://cs.ubc.ca/~van/papers/Simbicon.htm)). LMM: memory as motion matching's main limitation ([LMM paper](https://www.theorangeduck.com/media/uploads/other_stuff/Learned_Motion_Matching.pdf)).
- **Simplest thing that works.** Motion matching was a deliberately "brute-force" greedy approximation of Motion Fields ([Game Watch](https://game.watch.impress.co.jp/docs/news/749136.html); [arXiv 2510.22632](https://arxiv.org/html/2510.22632v1)). SIMBICON is a pose state machine plus one linear foot-placement rule ([SIMBICON PDF](https://www.cs.ubc.ca/~van/papers/2007-siggraph-simbicon.pdf)). Rain World is points connected at fixed distances ([Game Developer](https://gamedeveloper.com/art/video-animating-i-rain-world-i-and-its-many-squishy-stretchy-creatures)). FABRIK finds a point on a line instead of using angle matrices ([Aristidou](https://www.andreasaristidou.com/FABRIK)).
- **Borrowing across fields.** Robotics to animation (Raibert and Hodgins: [CMU RI](https://ri.cmu.edu/publications/animation-of-dynamic-legged-locomotion); Coros et al.'s Jacobian-transpose virtual forces from robotics: [paper](https://www.cs.ubc.ca/~van/papers/2010-TOG-gbwc/paper.pdf)). Procedural textures to motion (Perlin: [IEEE](https://ieeexplore.ieee.org/document/468392)). Evolutionary computation to creature design (Sims: [SIGGRAPH archive](https://history.siggraph.org/?p=119674)). Vision pose priors and adversarial training to motion style (AMP: [arXiv](https://arxiv.org/abs/2104.02180)).
- **Accidental and prototype-first discovery.** Jakobsson needed limbs to move and used code; he did not set out to do procedural animation ([Unity blog](https://unity.com/blog/exploring-procedural-design-rain-world)). Grow Home began as a physics programmer's procedural animation experiment whose "personality and charm" convinced the team to build a game ([Ubisoft News](https://news.ubisoft.com/en-us/article/7fDmgKCCwWJQtyoVoOvvGM/get-ready-to-grow-home)).
- **Experiment-driven refinement.** DeepMimic's key components were identified by ablation ([arXiv](https://arxiv.org/abs/1804.02717)). Hecker presented "what worked and what didn't" ([GDC 2007 page](https://chrishecker.com/How_To_Animate_a_Character_You%27ve_Never_Seen_Before)). AC3 applied a "Redo everything, but change nothing" acceptance test ([PC Gamer](https://www.pcgamer.com/gdc-2013-the-ai-tricks-behind-xcom-assassins-creed-3-and-warframe)).
- **Keep human intent in the loop.** Spore kept animator posing and keyframing, encoded semantically ([Hecker paper page](https://chrishecker.com/Real-time_Motion_Retargeting_to_Highly_Varied_User-Created_Morphologies)). Overgrowth kept keyed poses ([Polycount](https://polycount.com/discussion/comment/2093086)). Motion matching kept mocap and structured capture "dance cards" ([O3DE blog](https://docs.o3de.org/blog/posts/blog-motionmatching/)). DeepMimic and AMP kept reference motion as the style source ([arXiv DeepMimic](https://arxiv.org/abs/1804.02717); [arXiv AMP](https://arxiv.org/abs/2104.02180)).
- **Layer procedural corrections on top.** Clavet's procedural touch-ups after the search ([Game Developer](https://gamedeveloper.com/programming/most-inspiring-game-animation-tech-talks-of-2016)), AC's IK plus physics ([TechRadar](https://techradar.com/news/gaming/assassin-s-creed-iii-s-trailblazing-animation-legacy-lives-on-1140489)), and Ubisoft's predictive biomechanical foot IK ([GDC Vault](https://gdcvault.com/play/1023009/Fitting-the-World-A-Biomechanical)).
- **Build on a working baseline, then compress or learn it.** LMM replaced each stage of a working motion matcher with a network while keeping its behaviour ([Ubisoft La Forge](https://www.ubisoft.com/en-us/studio/laforge/news/3NWqwcMU9lMfumgfPAEfka/learned-motion-matching)). Coros generalized SIMBICON-style control ([Yin/Coros chapter](https://www2.cs.sfu.ca/~kkyin/papers/BipedController.pdf)).

### Inferences
- **A distilled working method** (synthesis; not stated by any single source):
  1. Name the constraint that rules out the standard method: unknown bodies, tiny team, precise controls, memory.
  2. Find the one physical or mathematical quantity that matters most (foot placement and center of mass for balance; foot positions and velocities plus trajectory for matching; distances between points for soft bodies; reach targets for limbs).
  3. Build a brute-force or single-rule prototype around that quantity in a playable test, and judge it by eye.
  4. Borrow solvers from other fields rather than inventing them (springs and PD control, inverted pendulum, nearest-neighbour search, IK such as FABRIK, coherent noise).
  5. Add layers one at a time, each answering an observed failure (foot IK on slopes, procedural touch-ups, ragdoll), and keep an "intent layer" (key poses, semantic tags, reference mocap) that artists control.
  6. Once it works, optimize, generalize or learn it (Coros after SIMBICON; LMM after motion matching), using the working version as ground truth.
  7. Share it, including failures (GDC talks, released code), which helped the next inventor in nearly every case here.
- **Relevance to a small browser-game avatar project** (inference): the cheapest proven entry points are Overgrowth-style few-pose interpolation with spring smoothing, SIMBICON-style foot placement from center-of-mass velocity (as a kinematic rule, not full physics), and FABRIK or two-bone IK for foot and hand contacts, with coherent noise for idle variation. Motion matching and RL-based control need large mocap data or training compute.
